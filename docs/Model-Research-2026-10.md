# Local Swarm Model Research, October 2026

## Executive conclusion

The current inventory is unusually strong for this machine. I found no later, independently verified 9–15B dense model with a Q5 GGUF small enough to clearly replace the current Qwen3.5/MiMo/Gemma/Ministral set. The clearest additions are not replacements: **Gemma 4 26B-A4B or 31B as the teacher**, and **Qwen3.5-27B as a second teacher**, both run alone. For the live swarm, keep model families diverse: Qwen/MiMo for the coordinator, Gemma or Mistral for an independent worker, and Granite Guardian when a specialist verifier is preferred.

All byte sizes below are the exact `size` values returned by the Hugging Face repository tree API on 2026-10-05. No model, tokenizer, or dataset file was downloaded. GiB values are approximate (`bytes / 2^30`).

## Compatibility and fit rules

- The 16 GB card is budgeted at about 14.5 GB for models. A second model beside the roughly 7 GB MiMo Q5 file therefore needs to stay near the brief's 8.5 GB ceiling, with practical headroom reserved for CUDA buffers and KV cache.
- A model marked **fits** satisfies the file-size screen, not a guarantee that every context length or parallel-slot setting fits. Start with the existing context budgets and measure.
- `llama.cpp` current source contains explicit `qwen35`, `qwen35moe`, `gemma4`, and GLM architecture support. That confirms current upstream direction, but does not prove that the repository's older CUDA build b10152 contains every later kernel or chat-template fix. Qwen3.5 and Gemma 4 should be treated as the safer paths; GLM-4.7-Flash should use a newer build if tested. Sources: [llama.cpp architecture list](https://github.com/ggml-org/llama.cpp/blob/master/src/llama-arch.h), [Qwen conversion support](https://github.com/ggml-org/llama.cpp/blob/master/conversion/qwen.py), [Gemma 4 loader](https://github.com/ggml-org/llama.cpp/blob/master/src/models/gemma4.cpp).
- Qwen3.5 defaults to thinking and uses a hybrid Gated DeltaNet/full-attention layout. Its no-thinking setting is a generation/chat-template parameter; `/think` and `/nothink` are not the Qwen3 soft switch. [Official Qwen3.5 card](https://huggingface.co/Qwen/Qwen3.5-27B/blob/main/README.md)
- Gemma 4 uses sliding-window attention and shared KV layers in its llama.cpp implementation; this is attractive for long passage accumulation. E2B/E4B are causal variants, while the larger multimodal variants have additional template and vision behavior. [llama.cpp Gemma 4 implementation](https://github.com/ggml-org/llama.cpp/blob/master/src/models/gemma4.cpp)

### Consequence for the rankings

The deeper pass changes three recommendations. **Apriel-1.6-15B-Thinker** belongs in the standalone teacher bake-off, and **Trinity Mini** belongs there as an independent MoE control. **InternLM3-8B** and **MiniCPM3-4B** become actionable comparison candidates because Q4/Q5/Q6 GGUFs exist and fit their roles. **Domyn Small** and **OLMo Hybrid** remain scientifically interesting 7–10B alternatives, but no verified Q4/Q5/Q6 GGUF and llama.cpp path was found. **Apertus 8B** remains the most immediately usable second-tier diversity worker because a Q5 GGUF exists and fits the file budget, although its published instruction-following result is not competitive with the strongest current Qwen/Gemma numbers.

### Quantization fallback policy

For this machine, the fallback order is **Q6 if it fits, then Q5_K_M, then Q4_K_M only when necessary**. For a live worker beside MiMo, treat about 8.5 GB as the practical file ceiling; for a standalone teacher, treat 24 GB as the hard total-file ceiling before runtime overhead. A Q4 candidate should be compared against the Q5 control on citation accuracy, JSON validity, refusal to invent evidence, and FRAMES rather than assumed equivalent because the file fits.

## Models considered but rejected for this PC

- **GLM-4.7-Flash:** impressive self-reported results for a 30B-A3B MoE: BrowseComp 42.8, GPQA 75.2, HLE 14.4 and SWE-bench Verified 59.2. However, its Q5 GGUF is **21,408,850,272 bytes** and its total model size is 30B; it is not an expert worker beside MiMo and is too close to the teacher memory ceiling once KV/runtime overhead is included. It also needs a current llama.cpp build check. [Official model card](https://huggingface.co/zai-org/GLM-4.7-Flash)
- **Qwen3.5-35B-A3B:** attractive 3B-active MoE, but Q5_K_M is **25,913,186,112 bytes**, over the 24 GB teacher ceiling. Its Q4 file is **20,836,243,264 bytes**, which fits the teacher file budget, but leaves little room for KV/runtime overhead and should be treated as a slow, borderline teacher experiment rather than a default recommendation.
- **Mistral 3 14B:** its Q5 file is **9,620,566,720 bytes**, above the expert's approximately 8.5 GB coexistence budget, but its Q4_0 file is **7,805,711,040 bytes** and therefore passes the revised file screen. It becomes a live expert-worker experiment at Q4, with an expected quality penalty versus Q5.
- **Nemotron Nano 9B v2:** a strong older baseline with a hybrid Mamba2/Transformer architecture and NVIDIA's official self-reported scores of GPQA 64.0, IFEval 90.3, HLE 6.5 and RULER 78.9 at 128K.
